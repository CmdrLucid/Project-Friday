# remake/ - the Landstalker remake (3D, own assets)

Goal: the whole world as real 3D models in STYLE C (user 2026-10-25, after three studies of Massan house A, `ASSETS.md`): smooth 'toy diorama' look = rounded modelled shapes, soft painted (procedural) materials, warm sun, ambient occlusion, soft shadows, depth of field; colours and proportions from the original. Pixel textures (the 2026-10-24 rule) are dropped. Figures stay pixel sprite billboards for now (`tools/rom_sprite.py` + `lib/massan_a.py: add_figure`; the user checks the mix first). CAMERA (user 2026-10-25): turns in 90 degree steps only (game projection), so the 4 facing directions of every sprite stay valid: shown direction = figure facing - camera quarter turns; figures are billboards turned to the camera (`lib/massan_a.py: face_camera`, previews `q1..q3.png`). SCALE: 1:1 the original (user 2026-10-25). Nigel is 31 units high with a 15 x 15 box (measured, FORMATS 'Entity struct' +54); his 47 px sprite = 31 + the depth of the box in the 2:1 view, so the original door (35) IS taller than Nigel; figure cards use 1 sprite pixel = 1/sqrt(2) units and stand at the box's front corner (`add_figure`, `FIG_PX`, `FIG_FWD`). Overlay check on the original picture: `R_ALIGN=1` (`~/.landstalker_remake/assets/massan_house_C_an_Originalstelle.png`). Plan: a material library (`lib/cmat.py`, preview `recipes/materials_c.py`) + a kit of parts (log wall, post, door, window, roof) so that further buildings are mostly assembly.
The recompiled game (`landstalker/`) stays the LOGIC CORE; the remake draws its state (plan: docs in `landstalker/docs/RENDERER_IDEAS.md`, 'Godot front end'). Logic changes are allowed in the remake only, as switchable hooks; with the remake off the original stays bit exact.

## Rules
- Assets are made ONE AT A TIME and shown to the user for approval before they are placed (the user's wish 2026-10-24). The list and its order: `ASSETS.md`.
- Only RECIPES, helper code and docs live in git. Everything generated (textures, GLB models, previews, room dumps) stays on the user's machine in `~/.landstalker_remake/` and is never committed. Textures are produced by our own generators (no ROM art); room data from the user's own ROM is local too.
- Units: 1 unit = 1 pixel of the original = 1/16 of a map cell; game coordinates x east, y south, z up (`landstalker/docs/FORMATS.md`, 'Height map = a real height field'). In Blender y = NORTH (game y negated), so nothing is mirrored and the GLB comes out x east, y up, z south.
- (Before style C) two ways to make an asset: (a) PROJECTION of the original pixels (`tools/rom_picture.py` cuts plane A of a room out of the user's ROM, optionally Scale2x; the recipe maps every vertex to U = x - y + 1184, V = (x + y) / 2 - z): exact from the game camera, hidden sides mirrored; (b) own generated pixel textures (`lib/blx.py`, `blx.PIXEL` = stepped light, no anti-aliasing, outlines). Previews: `blx.game_view` = the game's own 2:1 projection, so a render can be laid next to the original.

## Tools
- Blender (Flatpak) headless: `python3 remake/tools/build_asset.py <name>` runs `remake/recipes/<name>.py` with `remake/lib/blx.py` (pixel texture generator, mesh builder with planar 1 texel = 1 unit UVs, EEVEE preview renders, GLB export) -> `~/.landstalker_remake/assets/<name>/` (`<name>.glb`, `preview_*.png`).
- Rooms: `remake/lib/roomdata.py` (room data from the ROM, cell classes), `remake/lib/kit_c.py` (approved assets as builders), `remake/lib/cliff_c.py` (rock slopes), `remake/lib/house_c.py` (parametric log houses / tower), `remake/recipes/room_c.py` (whole room), `remake/tools/room_sheet.py` (sheet original | remake | turned views); see `ASSETS.md` 'Room blockout'.
- Node + kiln / loom / pxl / vex in `~/remake_tools` (INDEX 'remake toolchain') for quick props; Godot comes with the front end.
- MAP EDITOR (2026-10-27): `python3 remake/tools/editor.py [ROOM]` starts a local server (http://localhost:8765, this machine only) and opens `remake/editor/index.html` in the browser: original / remake render with a fade slider, zoom, every pixel card (pines, bushes, statue) with a marker; click = select (again = the card behind), drag / arrow keys = move on the ground, Page Up / Down = height, Del = delete, new cards from the props images, undo, save, 'Rendern' (Blender, ~1 min). Changes go to `remake/rooms/<room>.json` (IN git: our own placement decisions, no ROM content): `{"move": {card id: [dx, dy, dz]}, "delete": [ids], "add": [{kind, x, y, z}]}`; `recipes/room_c.py` applies them after its automatic placement (`R_EDITS=0` = ignore) and writes `cards.json` (ids, images, feet, cell heights) for the editor. Card id = image name @ automatic foot (game units); if the automatic placement changes, `room_c.py` prints 'card not found'. Since the second version the editor draws the cards ITSELF over a render without them (`nocards_<view>.png`, half size) so a moved card shows only at its new place (user: 'verwirrend wenn ich die Originalposition noch sehe'); views Spiel / 90 / 180 / 270 (Q / E; `cards.json` 'views': projection A game units -> editor pixels, row 3 = depth, card scale s, card origin offsets per view); houses cover cards behind them with the footprint rule of `sort_cards` via per-view house masks (`mask_<view>.png`, red = (house index + 1) * 28; a foot under a roof overhang counts as covered); 'Fertiges Bild' (F) shows the real render. Test server on another port: `EDITOR_PORT=8766`. Next: terrain heights, then 3D assets.
