# LESSONS and TO-DO backlog

Lessons learned (what cost time and how to avoid it) plus the prioritised backlog. Current state and the next steps in order: `HANDOFF.md`.

## 1. Lessons about method
1. **Always verify the build before measuring.** The user once ran an old build twice. After every ZIP: `bash tools/verify_build.sh` (markers + checksum). The startup banner `patch_timing v4` proves the timing patch.
2. **Do not guess what a sprite/entity is.** Identify by observed behaviour (speed, active frames; `tools/movers.py`, `entitytrack.py`) and let the user confirm. Wrong guesses cost a whole analysis round.
3. **Make ref and rec comparable before comparing**: same save (`genrecomp_ref` loads `.srm`), same dump phase (frame end), same input phase, replay recorded with the same timing. Otherwise differences are artefacts.
4. **Compare at the smallest level that still reproduces.** Whole-frame RAM diffs showed noise; function-level differential tests (funcdiff, Musashi vs generated C on the real RAM image) pinpointed the bug in one run. Instruction-level fuzz (insnfuzz) finds translation bugs without any ROM.
5. **Circular artefacts**: the interpreter log lists addresses that *generated code* falls into. If the generated code is wrong (function cut too early), the log contains garbage addresses; seeding them makes it worse. See 3.
6. **Undefined flags and random NPC directions are legitimate differences** (DIVU/DIVS N on overflow, BCD V, NPC walk directions). Filter them before declaring a bug.
7. **Timing is a whole-system property.** The visible symptoms (slow text, crackling music, `fm_update: clamped`) came from a single GPGX DMA stall, not from the instruction cycle table. Measure per context (`LANDSTALKER_CYCSTAT`) before changing the model.
8. **Document while learning**: symbols.json for every address, DEBUGGING.md for evidence, INDEX bug catalog for root causes.

9. **Check which binary the launcher starts.** `~/Landstalker.sh` has the project folder hard-coded; after switching to a new ZIP folder it kept starting the old build and a verified fix looked broken. After every new ZIP: `grep '^cd ' ~/Landstalker.sh` and fix with `sed -i`. Also: `tools/funcdiff/build.sh` used to link stale `.o` files (fixed in 853804d: only objects with an existing source).

## 2. Lessons about the code base
- Functions are cut at the sorted entry points; **a seed inside an instruction silently splits real code** (and the previous function then falls through into garbage). `tools/check_splits.py` finds these; build.sh runs it.
- `($XXXX).w` is sign-extended on the 68000. Generated temporaries must not share names with macro locals.
- capstone mis-decodes some forms (`roxr.b Dx,Dy`, 68020 full-format index words with bit 8 set) - filter or special-case, and cover with the fuzz.
- GPGX control-port DMA halts the 68K using the display-state rate; during active display this stalled 187k cycles. Charge at the blanking rate (patch_timing `bus_finish_dma`).
- The two cores initialise work RAM differently and keep stack leftovers (`$FF80-$FFB3`) - a stable ~44-byte difference is not a bug.
- NPC walking: a block tests collision only when a tile boundary is crossed, so a missing collision call shows up only at fences/walls (details HANDOFF section 6).

## 3. Rule: seeds from the interpreter log
**Never add a seed from the log without proving it is an instruction boundary** (`tools/disasm.py ROM ADDR` around it, `check_splits.py` after the build). If the generated code falls into an address, first ask why: is the previous function cut too early? Prefer fixing the cause (analyzer, data table, jump table) to adding a seed. Remaining "interp log" seeds in `gen_seeds.py` / `recomp.json` still to review: `0x0260DC 0x028F08 0x017C68 0x026112 0x0260D0 0x0260EE 0x017B48 0x025F98 0x025FB2` and the `0x003890` variant.

## 3b. Rule: heuristic scans must be bounded (but code is not only below $030000!)
genrecomp's address-table scan invents functions in any data. `recomp.json` carries `code_ranges` ([$200,$30000)); measure with `tools/code_extent.py` and explain findings with `tools/split_report.py`. After a change of the ranges: build, `check_splits`, regression pass. Findings of the analysis (2026-10-10): split_report classes P (pointer-only) and N (nothing refers) are bogus starts; R (real jsr/bsr target) are real entries and the CUT function is the suspect.

 29. **Overrides of generated functions: return protocol.** Generated code returns by popping the 68K return address (`func_table_rts`). Override that wraps the original: call it directly and continue afterwards only if the original ends with a normal RTS of its own frame (it returns to you); an override that replaces a function must end with `func_table_rts(); return;`; to call the original several times push the return address again (nested calls overwrite the old slot). Tail-call thunks (`jmp`) run their target AFTER your hook returns. Loops that the generator inlined (`goto` inside one function) cannot be hooked at their head.
