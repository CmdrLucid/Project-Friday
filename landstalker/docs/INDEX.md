## 5. Debug playbook (what worked)

1. Reproduce deterministically (replay) and find the first frame where REF and REC differ beyond the ~40-frame lead (`traj.py`, then `cmpdump.py`).
2. Read the startup/runtime log for `no function` / `RTS to` lines. Fix those before anything else (stack corruption shows up far from its cause).
3. Find what the CPU is doing: `LANDSTALKER_STACK`, then `CALLTRACE` for a few frames around the event; map addresses to source.
4. Per-frame dumps (`:1`) + diff consecutive frames to see which RAM ranges change when (a full game-loop pass touches ~270 ranges; idle frames only the frame counters).
5. Suspect an instruction translation? Hand-assemble it into a test ROM and compare with `genrecomp_ref` before theorising.
6. Write the root cause into this file (section 3) and DEBUGGING.md; keep 'Status' current.

### Interpreter fallback policy (decided with the user: NOT a permanent crutch)
`patch_interp.py` runs ROM code without a recompiled function on GPGX's 68K core. Treat it as a **discovery tool that shrinks to
zero**: play with `LANDSTALKER_INTERP_LOG=$HOME/interp.txt ~/Landstalker.sh`, run `python3 tools/seed_from_interp.py ~/interp.txt`
(adds the addresses as seeds; also put them in gen_seeds.py so ZIP updates keep them), rebuild: those routines are native next time.
In parallel derive script entry points statically from the script tables (every even `ScriptJump` word = code at base+word).
Goal: a full playthrough with an empty log; then make the fallback opt-in (`LANDSTALKER_INTERP=1`) and keep it only for debugging.

## Symbol rule (keep the code human readable; needed for modding)
**Confidence tiers in symbols.json (2026-10-12):** `auto-parent` = inner label `loc_XXXX` of a named function, named `<Parent>_locN` by `tools/name_inner.py`: the address is the one in the disassembly label name, the parent is the nearest preceding code label AND the label's XREF comment names that parent (proof that it lies inside it; kind `label`); `verified` = proven by call stack / log / disassembly of the ROM here; `inferred` = best guess (name or role); `auto-xref` = name taken from the lordmir disassembly, ALL referencing instructions found in the ROM point to this address (name is the disassembly's, address is proven; kind code/data NOT checked, hence kind `label`); `auto-xref-weak` = only a majority agrees, treat as a hint; `auto-seq` = address computed by walking the whole US disassembly in assembly order with a program counter (`tools/locate_labels.py DISASM_DIR ROM`: instruction sizes read from the ROM, data sizes counted, 4393 address-named labels used as checkpoints, all hit exactly except one that keeps another region's address); a name is accepted only when the checkpoints on BOTH sides matched, duplicate / module-local names are skipped; `auto-seq+xref` = both methods agree (independent). Kind `code` / `data` = what follows the label in the source. 1141 hand-verified names agreed with the walk; it also CORRECTED two old entries (Handle1sPause was the control-code table slot, CS_013C_1 had a bogus alias from a beta-region xref). ### Names for all functions (disassembly <-> ROM address), no assembler needed
`tools/extract_xrefs.py DISASM_DIR` (dev-time, needs the lordmir checkout) stores each named label's IDA XREF instruction addresses in
`tools/xrefs.json` (names + addresses only). `tools/symbolize.py ROM` decodes those instructions in the ROM (bsr/bra/jsr/jmp/lea pc/abs)
and writes `docs/symbols_auto.json` {addr: name}. Self-check printed: address-named labels (loc_25400) must resolve to their own address
(real ROM: 327/327 = 100%). build.sh runs it, output `docs/symbols_auto.json` is local/gitignored. Merge verified names into `docs/symbols.json`. Run on the Deck:
`python3 tools/symbolize.py "$ROM" && cp docs/symbols_auto.json ~/symbols_auto.json` and send the output / file.
